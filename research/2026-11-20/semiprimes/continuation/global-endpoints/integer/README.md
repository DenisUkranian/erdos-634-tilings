# Whole-board integer endpoint search

This directory contains a new unrestricted **search procedure**, not a solution
of either remaining semiprime case. Its current outcomes are recorded in the
run logs and `status.json` files. A solver timeout or a nonempty temporary-row
UNSAT core is inconclusive.

## Recorded outcome (20 November 2026)

**Both 3431 and 5063 remain open in this work.** No positive certificate or
globally unconditional UNSAT proof was produced for either case.

The final version-3 run for 5063 ended normally at the configured column
resource limit. Its last model had **150,597** generated placements,
**6,126** completed endpoint rows, **421,829** temporary physical rows,
**250,451** distinct active temporary guards, and **96** exact point cuts.
Its saved status is `column-resource-limit`; the preceding temporary UNSAT
cores were nonempty. A log entry saying `status unsat` refers to the model
with temporary finite-pool assumptions and is not a global impossibility
verdict. The completed row checkpoint and point file are exported as portable
JSON with deterministic gzip copies. The finite model can be regenerated
without shipping its 150,597-column list or large SMT journal.

The positive control `(a,b,c)=(5,3,7)`, `N=143`, returned a 143-tile model.
The separate stdlib verifier checked its exact metric, containment, area,
distinctness and physical endpoint-current cancellation. The same control
also passed after restarting from the portable `.json.gz` row and point
files. Independent audits additionally checked the 24-placement catalogue,
endpoint signs, wedge exclusions, pseudo-Boolean equations, shared guards,
and solver-context reconstruction. See `AUDIT_GLOBAL_INTEGER.md` in the
parent research package, or its accompanying independent audit material.

## Geometry and necessary constraints

For a tile with sides `(a,b,c)`, where `c²=a²+ab+b²`, use axial coordinates
`x+yρ`, `ρ=exp(iπ/3)`. The board has vertices `(0,0)`, `(A,0)`, `(0,B)`, with
`A=b(2a+b)` and `B=a(a+2b)`. The area ratio is `N=(a+2b)(2a+b)`.

A tile is encoded by its obtuse vertex `q`, height `h`, phase `j`, and handedness
`s∈{-1,+1}`. Its vertices are

```
q-a z^h ρ^j,  q,  q+b z^h ρ^(j+s),  z=(a+bρ)/c.
```

Coordinates are arbitrary normalized triples `(x,y,e)`, representing
`(x+yρ)/c^e`; the code has no imposed height, denominator, phase or radius cutoff.
The finite height lookup in `seed()` only decodes an existing finite seed.
Seed placements may all be removed. No old tile, cavity boundary, pair or local
scaffold is frozen.

An endpoint-current row is `(p,ell)`, where `ell` is an unoriented line direction.
For every side of a counterclockwise tile, put `-1` at its initial endpoint and
`+1` at its terminal endpoint. This is the negative of the usual oriented-boundary
convention. Summed tile rows equal the board rows in any tiling, including at
T-junctions.

Exactly 24 geometrical placements can meet one such row: three possible side
lengths, two rays, two assignments of the remaining side lengths, and two sides
of the line. `Geometry.inverse()` lists all of them. A completed row enumerates
every such placement that is contained and satisfies necessary boundary
arithmetic. It then imposes its exact Boolean balance, once and permanently.

The boundary arithmetic only says that every tile vertex on a board side is at
an integer distance in the additive semigroup generated by `a,b,c` from both
ends. In a tiling, the board side is partitioned into whole tile sides. A vertex
of another tile cannot meet the relative interior of one of these boundary
edges without an interior overlap. This justifies the condition even without
an edge-to-edge assumption.

All placements covering the exterior are enumerated separately. On each of the
three board sides, every admissible integer offset and all 24 incident placements
are examined. Exactly one selected tile covers each physical unit interval.
This is a complete finite enumeration of possible exterior sides, including
tilings using arbitrary other orientations and coordinates in the interior.

At each completed row, an additional valid at-most-one constraint is imposed on
each group of tiles sharing the same half-ray and same interior half-plane.
Any two such triangles have overlapping open wedges near their common vertex.
Finally, at most `N` of all currently known placements may be selected.

## Global quantifier argument

Fix any finite collection `R` of completed rows and include all boundary
placements. Every possible tile outside the generated pool has zero coefficient
on every row of `R` and covers no exterior unit interval. Therefore any actual
tiling induces a satisfying assignment of this finite necessary model: retain
its generated placements and omit its other placements. The count remains at
most `N`, and nonoverlap constraints remain satisfied.

Consequently, an exact UNSAT proof for this finite necessary model would exclude
**all** tilings, not only those in the current pool or orientation range. This
does not require every hypothetical tile in an arbitrary tiling to have a
coordinate in the generated ring: an omitted tile has zero coefficient on the
supported rows by the exhaustive 24-placement argument itself.

## Temporary rows and core-guided expansion

Every currently incident but uncompleted row also gets a Boolean-guarded
equality using just the current pool. The newest guard for every such row is
assumed for a search call. Old guards stay in the solver but are unassumed, so
they impose no restriction: they can all be false.

If an UNSAT core contains temporary guards, the corresponding endpoint rows
are candidates for completion. The next round may introduce all their missing
placements. Such an UNSAT result is **not** a global obstruction. An empty
temporary-guard core is a candidate global obstruction, but the program labels
it as needing an independent encoding and solver-proof audit. A Z3 log alone
must not be presented as a human-checked theorem or independent proof.

If all temporary rows are simultaneously satisfiable, every selected tile row
balances, so this is a candidate positive tiling. The separate
`verify_positive_solution.py` reconstructs triangles with independent rational
metric code, checks containment and congruence, and verifies exact physical
line-current cancellation. This cancellation implies multiplicity-one coverage
by the winding-number identity. It also implies no overlapping tile interiors.

## Reproduction

The only nonstandard solver requirement is the installed system `libz3.so.4`;
the program talks to its C API with `ctypes`. Install this directory as
`research/2026-11-20/semiprimes/continuation/global-endpoints/integer/` in the
existing repository. Its default seed loader locates the existing
`continuation/packing/packing_replay.py` relative to the repository; it contains
no absolute machine path. Alternatively `--seed-json` accepts the finite seed
as a JSON list of `[tile_key, positive_weight]` pairs. The seed is only an initial
pool, and never a constraint that requires retaining its tiles.

```
cd research/2026-11-20/semiprimes/continuation/global-endpoints/integer
python global_core_sat.py 35 13 43 --out run5063 --expand 60 --core-policy defect
python global_core_sat.py 33 7 37 --out run3431 --expand 60 --core-policy defect
python global_core_sat.py 5 3 7 --out control143
python ../verify_endpoint_tiling.py control143/solution.json
```

`--rows` accepts portable `.json` or `.json.gz`, or a trusted local pickle
checkpoint, and regenerates every saved complete row together with the seed
and full boundary. It is a semantic restart, not a restore of Z3's learned
clauses. `export_checkpoint.py` makes compact row-only and point-only JSON
files, with deterministic `.gz` copies. The large Boolean pool and SMT journal
need not be shipped: complete rows regenerate their entire incident pool.

```
python export_checkpoint.py run5063/checkpoint.pickle complete_rows_5063.json coverage_points_5063.json
python global_core_sat.py 35 13 43 --out resumed5063 \
    --rows complete_rows_5063.json.gz \
    --point-checkpoint coverage_points_5063.json.gz --core-policy defect
```

The optional coverage points add at-most-one constraints for the currently
generated tiles whose interiors contain each point. Containment uses exact
integer determinants. Ignoring other tiles only weakens these upper bounds,
so complete placement enumeration at a point is not required. The points do
not impose lower coverage bounds.

Version 3 shares a guard between identical temporary equations. All physical
rows currently represented by that guard are tracked, and core expansion
chooses from their union. A zero-target balance can be multiplied by `-1` for
canonicalization; no nonzero target is silently changed. Every ten rounds,
the Z3 context is rebuilt from **all** permanent assertions and current active
guards, discarding obsolete implications and learned state. The tile-count
bound is placed in one temporary `push` scope per search call; the scope
remains active during any unconditional UNSAT confirmation and proof export.
These changes affect memory use and search order only.

`--max-columns`, `--rounds`, and `--timeout-ms`
are computational resource limits only. Hitting any of them leaves the case
open. `--proof` enables Z3 proof output if a global UNSAT is reached; independent
proof checking is a separate requirement.
