# Global endpoint pricing for the two unit F2 boards

Research continuation, 20 November 2026. Denis Paliy project with ChatGPT assistance.

**Status:** this package supplies a new unrestricted search and exact certificate checkers. It does **not** contain a proof deciding either 3431 or 5063. Neither a complete positive tiling nor a passing nonexistence certificate for these two boards has been obtained in the recorded run.

## Targets and input certificates

For a primitive tile with short sides a,b and c²=a²+ab+b², the F2 target has axial vertices

```
(0,0), (b(2a+b),0), (0,a(a+2b)).
```

Its area is N=(a+2b)(2a+b) tile areas. All computations use the axial basis (1,exp(iπ/3)).

| N | Tile sides a,b,c | Target side lengths | Supplied signed seed |
|---:|---|---|---|
| 3431 | 33,7,37 | 511,1369,1551 | 3506 positive and 75 negative copies |
| 5063 | 35,13,43 | 1079,1849,2135 | 5071 positive and 8 negative copies |
| 143 | 5,3,7 | 39,49,55 | 143 positive copies, the constructive control |

The negative signs describe algebraic polygon indicators. They are not allowed in an ordinary tiling. The 3431 signed seed has some exterior placements; the search fixes every inadmissible positive column to zero, while artificial endpoint variables retain feasibility of the finite optimization problem.

The two-notch construction, and the 143 geometry from which the variable staircase was developed, belong to the previous project work. The staircase source credits Herdt and Bonfioli. See the [public staircase note](https://github.com/DenisUkranian/erdos-634-tilings/blob/main/research/2026-11-20/semiprimes/staircase/STAIRCASE.md) and [packing notes](https://github.com/DenisUkranian/erdos-634-tilings/tree/main/research/2026-11-20/semiprimes/continuation/packing). The JSON files here store exact unit coordinates, rather than relying on a transient workspace or importing an earlier script.

## What the method changes

An endpoint row consists of an exact point and an unoriented line direction. Each counterclockwise tile edge contributes one signed endpoint difference on that row. These differences cancel on interior contacts, including partial edge contacts and T-junctions.

For a specified row there are exactly 24 possible rigid placements having the point as an endpoint of a side on that axis: choose its side length, the other incident side length, direction and hand. Consequently finitely supported endpoint weights admit an **exhaustive finite global pricing test**. Every omitted placement with nonzero score appears in this test. This assertion has no orientation-height cutoff, translation-grid cutoff, or phase restriction. The independent checker generates the placements directly with the cosine law, separately from the search engine's orientation templates.

The search alternates between two operations. For fixed endpoint constraints it adds all positively priced new columns found by the global oracle. When the primary residual is zero, it examines the full boundary of a selected positive solution and adds missing endpoint rows. Adding a placement does not immediately force all its unrepresented endpoints to cancel; that premature constraint was the source of some misleading restricted-pool optimizations.

The finite LP also imposes a tile-count budget, positive weights at most one, and exact point-coverage inequalities. Each point inequality says that the signed weight of tiles strictly containing the point is at most one. Every ordinary tiling satisfies it. The strict-containment coefficients are computed exactly. Endpoints on the target boundary must have integral distances in the semigroup generated by a,b,c from both ends of the corresponding side; this necessary boundary arithmetic is explicitly declared in the final certificate.

The primary LP includes the fixed signed-seed negative columns and artificial endpoint residuals. Its objective is called **phase I**. It must not be described as the smallest possible number of negative tiles. A secondary LP, used only for constructive guidance, fixes negatives to zero and tries to retain as much of the positive seed as possible, first at exact total mass N. Neither optimization's value alone decides the board.

An optional minimum-L1 dual computation reduces the number of nonzero endpoint weights used for pricing. It targets a positive fraction of the current finite LP objective and handles the budget, point inequalities and positive-variable bounds. This is a search heuristic; its numerical output is never accepted as a proof without the exact checker.

## Exact stopping rules

A positive result must pass `verify_positive.py`. The program accepts only weights sufficiently close to zero or one, then discards the floating values and verifies exact rational coordinates. It checks N distinct congruent tiles, containment and equality of the full oriented endpoint boundary chains. Boundary equality and positivity imply coverage and disjoint interiors by winding number.

For a negative result, let B be the target score of a finite endpoint-weight table, let t_r≥0 be the penalties at chosen interior points, and define the adjusted score of a placement to be its endpoint score minus the penalties for points strictly inside it. Let S_N be the sum of the N largest positive adjusted scores among all potentially positive placements, padded by zeros. Then

```
B - sum(t_r) > S_N
```

excludes every ordinary tiling. At most N distinct tiles can be selected, and the total interior coverage of each penalized point is at most one. A tile with no endpoint in the finite support has nonpositive adjusted score, so no unenumerated positively scoring placements remain. The independent verifier checks every quantity with rational arithmetic.

A positive phase-I objective over an incompletely priced column list is not a negative result. A zero phase-I objective satisfying only the currently installed rows is not a positive result. A complete fractional positive solution is also not an ordinary tiling. Budget exhaustion, a solver timeout, and an interrupted run give no mathematical verdict.

## Run and reproduce

Python 3, NumPy and SciPy are required for the search. The recorded runtime used NumPy 2.3.5 and SciPy 1.17.0. The independent certificate checkers use the Python standard library.

Run the constructive control from a separate working directory:

```sh
python /path/to/package/solver.py 5 3 7
python /path/to/package/verify_positive.py positive_solution_143.json 5 3 7
python /path/to/package/verify_endpoint_dual.py --self-test
```

The recorded result is 143 exact positive tiles, zero negative mass, zero endpoint residual, no violated point cuts, and successful independent verification.

Start a target search:

```sh
LP_LIMIT=120 CUTS_PER_ITER=24 MAX_POINT_CUTS=480 \
GROW=1000 BATCH=3000 \
python /path/to/package/solver.py 35 13 43
```

Use `33 7 37` for 3431. Seeds are read from the package directory by default. `SEED_JSON` selects a different exact seed. Checkpoints are saved atomically in the working directory, so different target runs should use different working directories.

```sh
RESUME=checkpoint_5063.pickle LP_LIMIT=120 \
python /path/to/package/solver.py 35 13 43
```

Selected controls:

- `ITERATIONS`: final iteration index, default 10000.
- `LP_LIMIT`: time limit for each numerical LP; a timeout does not prove infeasibility.
- `ARTIFICIAL_COST`: endpoint-residual penalty, default 1.
- `CUTS_PER_ITER`, `MAX_POINT_CUTS`, `CUT_CENTROIDS`, `CUT_PAIRS`: finite cut-discovery limits. They affect search strength, not the exact meaning of an installed cut.
- `GROW`, `BATCH`: maximum new endpoint rows and newly priced columns per step.
- `JOINT_ROWS=1`: add missing endpoint rows and point cuts in the same zero-residual iteration. Set to 0 to process new point cuts first.
- `SPARSE_DUAL=1`, `SPARSE_THRESHOLD`, `SPARSE_FRACTION`, `SPARSE_LIMIT`: optional dual-support reduction. Disable with 0.
- `STEER_EXACT_AREA=1`: try the secondary heuristic at total positive mass N before falling back to the inequality budget.

A proposed `GLOBAL_CERT_N.json` is only a candidate until this command succeeds with `verified_global_nonexistence: true`:

```sh
python /path/to/package/verify_endpoint_dual.py GLOBAL_CERT_N.json
```

No such successful target certificate is included in this package. Independent mathematical review of the new method and its implementation remains outstanding.
